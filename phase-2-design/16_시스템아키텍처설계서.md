- Project: DRAFT → ACTIVE → ON_HOLD → CLOSED
- Patent Review: CANDIDATE → SCREENED → CLAIM_ANALYSIS → LEGAL_REVIEW → DECIDED → MONITORING
- Risk: CRITICAL / HIGH / MEDIUM / LOW / CLEARED
- Gate: NOT_STARTED / IN_REVIEW / PASSED / CONDITIONAL / REJECTED
- Decision: DESIGN_AROUND / LICENSE / INVALIDITY_REVIEW / ACCEPT / STOP / MONITOR

## 5. 논리 아키텍처
```mermaid
flowchart LR
  U[Browser] --> WAF[WAF / Reverse Proxy]
  WAF --> WEB[Web SPA/SSR]
  WEB --> API[API Service]
  API --> DB[(PostgreSQL)]
  API --> OS[(Object Storage)]
  API --> SRCH[(OpenSearch/Vector Index)]
  API --> Q[Job Queue]
  Q --> WK[Worker]
  WK --> PAT[Patent DB Connectors]
  API --> AIGW[AI Gateway]
  AIGW --> LLM[LLM/Embedding]
  API --> IDP[Enterprise IdP]
  API --> AUD[Audit Sink]
  PLM[PLM/PDM] --> API
```

### 아키텍처 결정
- Modular Monolith 우선(MVP), 검색/AI/worker는 분리 가능
- PostgreSQL을 시스템 오브 레코드로 사용
- 특허 원문/파일은 Object Storage
- Full-text + vector hybrid search는 별도 index
- 외부 특허/LLM 호출은 Worker/AI Gateway에서 통제
- Project-level authorization은 모든 query에 강제

### 주요 이벤트
- DESIGN_REV_CHANGED
- CLAIM_VERSION_CHANGED
- PATENT_STATUS_CHANGED
- RISK_ESCALATED
- GATE_REVIEW_REQUESTED
- WATCH_MATCH_FOUND
