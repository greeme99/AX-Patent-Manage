# 19. 프롬프트 엔지니어링 가이드

## 1. 문서 정보
- 프로젝트: 설계특허관리 웹앱 (Design Patent/FTO Management Platform)
- 기준일: 2026-08-25
- 상태: Draft v0.1
- 근거: 제공된 특허업무/기술특허 관리 가이드 및 Phase 문서 작성 가이드

## 3. 범위

## 5. 프롬프트 표준
### System 규칙
- 사용 가능한 근거만 사용
- 추정은 명시
- 법률 결론 대신 “검토 필요”로 분리
- Claim 문언을 임의로 축약해 법적 의미를 확정하지 않음
- 모든 핵심 주장에 source ID/citation 연결
- JSON schema 출력 시 enum 준수

### Claim 요소 추출 템플릿
```text
역할: 특허 분석 보조.
입력: 독립청구항 원문.
작업: 문언 순서를 보존하며 기술적 요소 후보로 분리.
금지: 침해판단, 등가론 결론.
출력: [{element_id, exact_text, normalized_feature, ambiguity, citation}]
```

### Claim Chart 초안 템플릿
```text
claim_element와 허용된 project evidence만 비교한다.
mapping은 YES/PARTIAL/NO/UNKNOWN 중 하나.
rationale에는 evidence_id를 반드시 포함한다.
근거가 없으면 UNKNOWN.
```

### Prompt 버전관리
prompt_id, version, owner, use_case, model, schema, eval_set, approved_at
